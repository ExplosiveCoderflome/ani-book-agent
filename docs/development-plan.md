# 小说 Agent 开放创作平台开发计划

> 目标：把当前应用升级为一个以 Mastra 为唯一执行运行时、以小说资产和作者决策为事实来源、能够自动帮助用户从零完成整本小说的开放创作平台。
>
> 设计原则：开放的是能力组合和创作资产，不开放第二套 Agent Runtime、Workflow Runtime、状态机或事实数据库。用户可以扩展 Skill、Agent Profile、Tool Capability 和资产类型，但所有运行仍由 Mastra 执行，所有权威提交仍由 Domain 校验。

## 当前基线（2026-08-16）

已具备：

- Mastra 原生 Agent 对话、Reasoning、Tool、Approval、Task、Attachment 和 Workflow Stream。
- 小说工作台三栏布局、生产导航、工件编辑、作者保护和运行恢复。
- 小说简报、故事圣经、世界设定、角色阵容、卷战略、卷骨架、章节生产、连续性、质量修复、完本验收和 TXT 导出。
- Markdown/YAML 工件权威、`novel-state.yaml` 进度权威、Mastra Run 执行权威。
- `present_chat_choices` 已开始接入，作为对话快捷选择的真实 Agent Tool。
- 平台能力目录已返回内置 Skill、Agent Profile、Workflow、Tool Manifest 和默认项目配方。
- 左侧已改为平台导航：当前任务、作品资产、创作能力；生产链使用 Mastra `Entity` 折叠展示。
- 中间已提供资产中心和能力中心：资产筛选、依赖/引用、作者保护、权威工件入口，以及 Skills/Profile/Workflow 合同查看。

未完成：

- Studio 通用能力仍未完全平台化：Trace/评估工作区和用户级配置持久化尚未统一。
- 无想法入口仍只有自由聊天，缺少五条种子和两份简报预览协议。
- 资产管理仍以工件列表为主，缺少统一资产类型、关系图、版本、来源和引用面板。
- 自动导演仍偏向章节范围，尚未成为从开书到完本的默认导演。
- 完本验收主要覆盖最终卷，尚未建立全书级承诺、人物弧、质量债和伏笔汇总。
- Prompt Manager 仍是全局模板编辑器，尚未升级为项目级生产配方与 Skill 组合。

## 平台架构

```text
Creator Workspace
├─ Project Recipe        作者可理解的生产配方
├─ Skill Registry        可版本化、可启停、可组合的能力包
├─ Agent Profiles        对话、导演、规划、正文、审查等角色配置
├─ Tool Manifest         只读、工作区写入、资产操作、运行操作能力
├─ Asset Graph            故事、世界、角色、关系、伏笔、章节和参考资料
├─ Mastra Agent/Workflow 唯一执行运行时
└─ Domain Commit Gate     权威事实、状态、权限、幂等、保护和 stale
```

依赖方向保持：

```text
Web / Mastra / Infrastructure → Application → Domain
```

Skill、Agent Profile 和 Tool 只描述能力与约束，不能自行写权威文件或启动第二套运行循环。

目标：把开放平台需要的公共对象先固定下来，避免后续每个功能各自发明协议。

- [x] 统一 Studio 消息 Part 和工具展示入口。
- [x] 接入 Mastra 原生聊天、线程、审批、Workflow observe。
- [x] 增加 `present_chat_choices` Tool，快捷选择不再依赖第二次模型调用。
- [x] 新增 `SkillDefinition`、`AgentProfile`、`ProjectRecipe` 合同，并通过能力接口统一投影。
- [x] 新增版本、来源、启用范围、依赖、上下文预算和安全边界字段；Tool Manifest 由 Mastra Agent 能力目录投影。
- [x] 为平台合同增加 Schema 校验和最小单测。

退出标准：任何开放配置都能被解析、校验、版本化，并且不能绕过既有 Domain/Workflow 提交门禁。

## 阶段 1：真正的新手开书入口

目标：支持“完全没有想法”到可确认的书级方向，并降低第一次决策负担。

- [x] 无想法请求输出恰好五条一句话种子：强钩子、人物成长、设定奇观、关系牵引、悬念追查五种创意功能。
- [ ] 种子只作为非权威预览，允许选择、编辑、混合或放弃。
- [ ] 选中种子或输入想法后生成恰好两份差异明显的新书简报预览。
- [ ] 两份预览必须包含：书名、premise、目标读者/回报、主角路径、核心冲突、前期钩子、推进循环、终局方向。
- [ ] 预览未确认前不得写入 `novel-brief.md`，不得驱动世界、卷和章节生产。
- [ ] 将开书设置拆成两轮，每轮最多三个高影响决定。
- [ ] 为新手提供“交给 Agent 决定”并记录为可撤回的项目级委托。
- [ ] 为快捷选项增加真实 Tool Result / `data-*` Part 的浏览器闭环测试。

退出标准：空白用户可以在不填写专家表单的情况下得到可比较方向，并确认一份可执行书级合同。

## 阶段 2：小说资产管理中心

目标：从“文件列表”升级为可追踪的小说资产系统。

资产类型：

- 书级：小说简报、故事圣经、世界规则、角色阵容、生产配方。
- 结构级：卷战略、卷骨架、节奏板、卷间承接。
- 叙事级：章节计划、章节正文、章节审查、质量债、连续性更新。
- 关系级：人物关系、势力关系、资源、事件、伏笔、承诺和读者问题。
- 外部级：作者资料、参考资料、灵感、附件和导入文件。

功能：

- [x] 新增 `AssetRecord`：类型、标题、路径、版本、来源、状态、保护、依赖、引用、更新时间和哈希。
- [x] 资产投影提供依赖、引用和 stale 所需的关系字段；完整图视图和影响范围操作待补齐。
- [x] 新增资产中心导航、类型筛选和标题/路径/标签定位；状态筛选和全文内容检索待补齐。
- [ ] 资产正文、结构化字段、来源证据和修改历史分层展示。
- [ ] 允许 Agent 创建非权威提案资产，但只有 Workflow 提交后才能成为稳定资产。
- [ ] 允许作者导入 Markdown/YAML/TXT/JSON，并生成待确认资产，不直接覆盖权威内容。
- [ ] 章节上下文包显示本章使用了哪些资产、哈希和省略了哪些内容。
- [ ] 角色、世界规则、伏笔和关系支持从章节反向查看出现位置。

退出标准：用户能回答“这条信息来自哪里、影响什么、被哪些章节使用、修改后哪些内容会 stale”。

## 阶段 3：Skill Registry 与 Agent Profile

目标：开放可组合能力，但不把用户变成运行时开发者。

Skill 类型：

- 题材 Skill：玄幻、悬疑、都市、历史、科幻等阅读回报模板。
- 结构 Skill：快节奏、慢热、群像、单线、强悬念、强情感等。
- 写作 Skill：第一人称、第三人称、对话密度、叙事距离、语言质感。
- 审查 Skill：连续性、人物声音、节奏、重复、钩子和敏感边界。
- 资产 Skill：角色卡、世界规则、关系图、伏笔台账和资料库。

实现：

- [ ] 声明式 `SkillDefinition`，包含输入合同、输出合同、作用阶段、上下文预算、允许 Tool 和停止条件。
- [ ] 内置 Skill 与用户 Skill 分离存储，支持版本、启用、禁用、回滚和冲突提示。
- [ ] 新增 `AgentProfile`：对话、导演、规划、正文、审查、资产整理等角色。
- [ ] Agent Profile 只能组合已注册 Skill 和 Tool，不允许用户上传任意执行代码。
- [ ] 将当前全局 Prompt Manager 收敛为“项目生产配方”编辑器。
- [ ] 配方修改影响新运行，运行中使用启动时快照。
- [ ] Skill 冲突时由 Domain 给出阻断或需要确认的影响报告。

退出标准：用户能说“这本书以后按这种节奏和风格自动写”，系统可以持续复用且不会改变权威事实。

## 阶段 4：自动导演 2.0

目标：让自动导演从章节工具升级为全书生产主线。

- [ ] 开书方向确认后自动生成书级规划队列。
- [ ] 将书级里程碑、卷配置、章节范围、审批策略统一为导演计划。
- [ ] 用户只在书级方向、卷战略、结构性重规划和完本验收处确认。
- [ ] 普通章节自动完成：计划 → 上下文 → 正文 → 人性化 → 审查 → 修复 → 连续性。
- [ ] 卷结束自动生成卷间承接包并进入下一卷配置。
- [ ] 支持暂停原因、预计影响、恢复入口和下一步唯一投影。
- [ ] 运行失败自动区分模型失败、上下文失败、结构失败和作者冲突。
- [ ] 允许用户设置自动生产批次，但永远保持单书单链串行。

退出标准：用户确认开书方向后，不需要手动理解每个工件名称，也能稳定推进到目标卷或完本。

## 阶段 5：全书级质量与完本

- [ ] 全书承诺台账：种子、触达、施压、部分揭示、兑现、失效原因。
- [ ] 全书人物弧台账：欲望、选择、能力、关系、代价和终局状态。
- [ ] 全书质量债聚合，覆盖所有卷和章节。
- [ ] 完本验收覆盖所有卷，不只检查最终卷。
- [ ] 增加前三章、每 3–5 章、每卷末的读者回报检查。
- [ ] 增加首章压力、首章可见变化、章末拉力的结构化评分。
- [ ] 增加重复冲突形态和中段拖沓检查。
- [ ] 完本失败时生成可执行修复队列，而不是只返回阻断列表。
- [ ] 只有全书承诺、人物弧、章节完整性、连续性和质量债通过后才能标记完本。

退出标准：导出的不是“有很多章节的 TXT”，而是一部经过全书级结构和连续性验收的小说。

- [x] 增加基于 Mastra Observability Storage 的运行统计：成功率、耗时、Token、Span、工具调用和最近运行。

- [ ] Dataset 与 Scorer 绑定 Skill/Prompt/Model 版本。

- [ ] 失败运行可以从现有 Run 观察、恢复或复制为实验运行。
- [ ] 保持小说工作台为作者主入口，Studio 只作为开发和质量实验室。

## 阶段 7：体验与发布验收

- [ ] 无想法 → 五种种子 → 两份预览 → 开书确认闭环。
- [ ] 方向确认 → 自动书级规划 → 首卷配置闭环。
- [ ] 自动导演 → 单章生产 → 卷间承接 → 下一卷闭环。
- [ ] 结构性审查暂停 → 作者确认 → 恢复闭环。
- [ ] 作者修改 → stale 传播 → 定向重生成闭环。
- [ ] 全书验收 → 导出 → 刷新恢复闭环。
- [ ] 桌面三栏、窄屏抽屉、移动端输入和附件闭环。
- [ ] `pnpm test`、`pnpm typecheck`、`pnpm build:web`、`pnpm build`、`git diff --check`。

## 明确不做

- 不引入第二套 Agent 或 Workflow Runtime。
- 不让自定义 Skill 直接执行任意代码。
- 不让 Agent 直接覆盖权威 Markdown/YAML。
- 不把 SQLite、向量索引或 Memory 当成小说事实来源。
- 不把 Studio 的开发者界面强行暴露给普通作者。
- 不为了“开放”增加用户必须理解的 Agent、Tool、Trace 和状态机概念。
