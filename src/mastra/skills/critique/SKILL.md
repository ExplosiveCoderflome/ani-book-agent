# 独立验收

`accepted`：章节职责、连续性和阅读回报成立。
`repair`：问题可通过一次有限修订解决。
`replan`：章节目标与蓝图、卷计划或稳定事实结构性冲突，改文字也无法解决。

检查主角行动、冲突升级、可见净变化、旧线索承接、角色知情边界、世界规则、语言可读性和章末牵引。必须逐段对照上一章：复制、近似改写或重新表演上一章主体内容时禁止 `accepted`。每个问题提供正文证据和可执行修复。连续性只抽取最终正文中已经发生的事实，不把计划、威胁、谎言和猜测写入账本。

`continuityDelta.characterUpdates` 只提交本章造成的角色净变化：姓名或身份发生正式变化时更新 `name`/`role`，当前目标改变时更新 `goal`，身体、位置、资源或处境改变时更新 `state`，新获知且被正文证实的信息加入 `knowledge`。`relationships` 一旦提供，必须是该角色截至本章结尾的当前关系摘要，不是历史关系堆叠。新登场且会继续影响剧情的角色应给出稳定 `id`、姓名、身份、目标和当前状态；一次性路人无需入账。

若最终正文引入了会持续影响后续剧情、但 `book/characters/<id>.md` 尚不存在的新角色，在 `newCharacterProfiles` 中创建一份独立角色档案；`id` 使用小写英文或数字短横线并与账本一致，`content` 遵循 character-planning Skill 的单角色文件结构。只根据蓝图和正文证据写当前可确认的长期叙事功能、行为声音、关系张力与近期人物弧，不虚构终局。已有角色档案不在章节验收中机械重写；若正文使其长期设计结构性失效，应判为 `replan`，交由作者确认。
