# 角色规划与同步

## 任务边界

用于新建、补全或调整角色档案、人物弧和关系网。新书开书阶段尚无角色文件时，直接根据作者已确认方案创建角色档案，不读取不存在的 `book` 目录或文件。补全或调整已有角色时，先用 `read_project` 的空 `paths` 获取文件清单，再读取清单中存在的 `book/blueprint.md`、`book/characters/<character-id>.md` 和 `book/ledger.yaml`；需要核对实际进展时再搜索相关章节。不要猜测路径，也不要凭聊天记忆改写已有角色事实。

- `book/characters/<character-id>.md` 每个文件只保存一个角色的长期创作设计；`character-id` 必须与账本中的角色 `id` 一致，并在角色改名后保持不变。
- `book/ledger.yaml` 保存截至最新稳定章节已经成立的当前事实：目标、状态、知情范围和关系现状。
- 计划中的转折、背叛、死亡、秘密揭露不能提前写进账本；正文已经发生的变化不能只留在角色档案里。

## 规划标准

只规划会进入故事并承担功能的角色。新手输入不足时给出明确默认方案，不把专业问卷交给作者。每个主要角色至少写清：

1. **叙事功能**：他给主线带来什么压力、帮助、镜像或诱惑，移除后故事会损失什么。
2. **外在目标与内在需要**：当前主动追求什么；真正需要面对但尚未承认什么。
3. **核心矛盾**：欲望、价值观、能力或处境之间可反复制造选择的冲突。
4. **能力与限制**：能解决什么、不能解决什么，以及使用优势的代价。
5. **外貌与辨识特征**：年龄感、身形轮廓、五官或气质、常见服饰，以及能在场景中反复识别的一至两个动作或物件。优先写可被他人观察、可进入正文的具体特征，不堆空泛的美丑形容词；该字段不得留空或写“待确认”。
6. **行为与声音**：压力下的决策倾向、表达习惯和不能随意漂移的行为辨识点。
7. **秘密与知情边界**：秘密内容、当前知情者、允许揭露的阶段。
8. **关系张力**：双方各自想从对方得到什么、当前关系、主要摩擦和可能改变关系的事件。
9. **人物弧检查点**：当前起点、本卷必须出现的选择、下一次不可逆转折、终局方向；写转变条件，不预写死全部情节。

配角采用与戏份匹配的精度；一次性功能角色不扩写完整传记。角色之间必须目标相交，不能各自拥有互不相干的背景故事。

## 文件合同

每个角色使用一个独立文件，例如 `book/characters/hero.md`、`book/characters/mentor-lu.md`。不要把多名角色重新合并到一个 Markdown，也不要按角色姓名重命名已有文件。每个文件使用以下稳定结构，已有内容只做必要更新：

```md
# 角色名

> 角色 ID：hero

- 叙事功能：
- 外在目标：
- 内在需要：
- 核心矛盾：
- 能力与限制：
- 外貌与辨识特征：
- 行为与声音：
- 秘密与知情边界：
- 关系张力：
- 人物弧检查点：
- 不可漂移项：
```

提交前对照账本：若角色的当前姓名、身份、目标、状态、知识或关系现状也应变化，在同一个 `propose_patch` 中同步更新 `book/ledger.yaml`。账本中的 `knowledge` 和 `relationships` 必须是字符串数组；每条关系写成“对方角色 ID：当前关系——已成立依据”，例如 `"mentor: 师徒——导师已经收主角入门"`，不得写成 `{ id, type, note }` 对象。每个角色文件都是独立 change，替换前必须读取并携带它自己的 `baseSha256`；只改一个角色时不得连带重写其他角色文件。只输出有依据的变化，不为了填满模板发明正文尚未发生的事实。
