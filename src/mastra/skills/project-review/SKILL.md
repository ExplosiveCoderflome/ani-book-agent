# 通用项目审查

- 作者的审查目标是本次评价合同。自行选择与目标有关的检查维度，不套固定清单，也不扩张到无关问题。
- 以正文、蓝图、账本和卷计划的实际内容为证据；计划中的事件不等于正文已经发生，推测不等于稳定事实。
- 跨文件比较人物状态、知情边界、时间、地点、资源、因果、世界规则、承诺与实际推进时，指出冲突两端的真实路径和短摘录。
- 区分明确矛盾、信息缺口和可接受的悬念。没有直接证据的问题不要报告，不用个人偏好冒充错误。
- 标题、说明和建议必须与证据表达同一件事，不能把“计划如此但正文未发生”误写成“账本已经记录为发生”。
- 建议说明最小修复位置和预期效果，但不直接改写权威文件。
- 严格输出调用方提供的结构化 Schema；分类名称由当前目标决定，不依赖预设枚举。
